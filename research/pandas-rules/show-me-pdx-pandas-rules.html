Proposed rules

Each block shows the code a rule reports and the code it asks for. A safe fix runs with pdx check --fix, and it keeps the result apart from float rounding below 1e-12, which 3 of the 31 test cases showed. An unsafe fix needs --unsafe-fixes.

Code that is wrong or broken on pandas 3 12 rules

Severity is error. Each old form was run on pandas 3.0.6 and 3.1.1 to confirm the failure.

chained-assignmentunsafe fixexists, fix needs repair
- df[df["a"] > 1]["b"] = 0+ df.loc[df["a"] > 1, "b"] = 0

The rule exists, but its fix is wrong for the mask shape. pdx 0.1.0 rewrites the line above to df.loc["b", df["a"] > 1] = 0, with row and column swapped. The fix needs one form per shape.

inplace-on-columnunsafe fixexists as no-inplace
- df["b"].fillna(0, inplace=True)+ df["b"] = df["b"].fillna(0)

The column stays unchanged on pandas 3.1.1, and pandas only warns. Today no-inplace reports the line as a warning about style, so the proposal is to report it as an error.

inplace-result-assignedunsafe fixprototype ran
- df = df.dropna(inplace=True)+ df = df.dropna()

The name df is None after the line runs.

epoch-from-int-castreport onlyprototype ran
- df["d"].astype("int64") // 10**9+ (df["d"] - pd.Timestamp("1970-01-01")) // pd.Timedelta("1s")

Datetimes default to microseconds in pandas 3. The old form returned 1704067 for 2024-01-01, and the correct value is 1704067200.

The in operator checks index labels. It returned False for a value that was in the column.

The first form raised TypeError here. A shorter one, df["a"] == 1 & df["flag"], runs and returns a different mask.

The write raised ValueError, because arrays taken from a frame are read-only under copy-on-write.

Features with no old form to detect

A rule can only promote a feature when the longer code it replaces has a shape pdx can match. pd.merge_asof was 38 times faster than a lookup loop over 5,000 timestamps, and the loop can be written in many ways. A window over time, such as rolling("7D", on="d"), differs from rolling(7) only when dates are missing. resample was 2.6 times faster than a groupby on a sorted frame and much slower on an unsorted one. pdx cannot see whether a frame is sorted. The messages of row-loop and text-time-key can name all three features.

Support for pandas 3.0 with one rule set

4 rules ask for an API that exists only in pandas 3.1. On pandas 3.0.6 df.select raises AttributeError, so pdx has to know the installed version before it reports or fixes those rules.

on(pdx check)
  version = pandas version in the project's .venv, read from the name of the dist-info folder
  if no pandas is installed
    version = 3.1
  for each rule
    if rule.metadata.since is newer than version
      skip the rule
    report the rule, and apply its fix when asked

Suggested build order

  1. Repair the chained-assignment fix and add the other 11 rules for code that is wrong or broken on pandas 3. They are errors, and most have a fix.
  2. Add the rules with a safe fix and a measured gain, such as groupby-lambda, rolling-apply, copy-after-indexing and lambda-column.
  3. Add the rules that only report, such as row-loop, apply-axis-1 and groupby-apply.
  4. Add the version lookup and the 4 rules that need pandas 3.1.

Method: each pair ran on pandas 3.1.1 and 3.0.6 with Python 3.15.2, numpy 2.5.4 and pyarrow 26.0.1, on a machine with 32 cores. A time is the best of 1 to 5 runs on a frame held in memory, and the two results were compared after each pair. The whole set ran twice. The gains from the two runs differed by 4% at the median and by 50% at most, and the page shows the second run. The scripts and the raw times are in research/pandas-rules in the pdx repository, and the 60 prototype rule documents are in research/pandas-rules/proto/rules.yml.
